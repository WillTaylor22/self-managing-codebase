# Escalated PRs have no agent-side cleanup mechanism

Step 7's stale-PR rule only fires when `most recent commit > 24h ago AND last reviewer comment is AGENT_REVIEW: REQUEST_CHANGES`. PRs whose last reviewer comment is `AGENT_REVIEW: ESCALATE` are explicitly off-limits to the agent (hard rule: "leave the PR alone" after 3-round escalation). Combined, this means escalated PRs accumulate indefinitely with no agent surfacing: PR #12 has been open in ESCALATE state since 2026-05-26 (12+ days as of this session), the trivial merge-conflict fix described in the round-3 farewell comment is still pending, and every future session will (correctly) skip it. If this becomes a real problem (e.g., escalated PRs blocking merges or polluting the open-PR view), the fix belongs in the system prompt — extend step 7 to also close PRs whose last reviewer comment is `ESCALATE` and which haven't had a human commit in N days, OR have the manager file a Linear "abandoned PR" ticket on first sighting. Don't try to invent the rule mid-session.
